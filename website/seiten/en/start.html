See what happens — before it happens.

{{ symbol:shield }} Security

A tool with access to your data has to be strict.

phpdbadmin was built from the start against a threat model and reviewed following OWASP — in two passes, with no open high finding.

  • {{ symbol:key-round }}

    Sign in without a password

    With a passkey or a code by email. There are no account passwords to guess or steal.

  • {{ symbol:lock }}

    Credentials encrypted

    Connection passwords are stored encrypted in the app database — or not at all, if you enter them for the session only.

  • {{ symbol:network }}

    Only allowed servers

    You decide which servers phpdbadmin may connect to. That keeps detours into your internal network closed.

  • {{ symbol:users }}

    Privileges per connection

    Read, write, manage — per account and connection. phpdbadmin warns when a database account holds every privilege on the server.

  • {{ symbol:shield-check }}

    Hardened

    Content Security Policy with nonces, CSRF protection, throttled code checks, no telemetry. Nothing phones home.

  • {{ symbol:signature }}

    Signed releases

    The installer checks size, SHA-256 and the Ed25519 signature of every release before it unpacks anything.

{{ symbol:globe }} With the web installer

For web hosting without a console — a single PHP file.

  1. Create a (sub)domain of its own, e.g. db.your-domain.com, and switch on HTTPS.
  2. Upload phpdbadmin-installer.php into its empty folder.
  3. Open the file in the browser and follow the steps.

The installer checks the server and explains every finding in plain language, recognises around 20 hosting providers, fixes what it can after asking, verifies the release signature, places the program outside the web folder where possible, sets up the app database, mail and your account — and deletes itself at the end.

{{ symbol:terminal }} With the console

For your own server, a VM or Laravel Herd.

$ git clone {{ repository }}.git
$ cd phpdbadmin
$ composer setup

composer setup installs the dependencies, builds the interface, sets up the app database, checks the system and asks for your name and email address. At the end you get a setup link that signs you in and creates your passkey.

Updating: git pull and composer upgrade.

Requirements

PHP
8.5 with pdo, mbstring, openssl — plus the driver per database (pdo_mysql, pdo_pgsql, pdo_sqlite)
Web server
Apache, nginx, LiteSpeed or Caddy with PHP-FPM — or Laravel Herd, Valet, php artisan serve
App database
SQLite (default), MariaDB, MySQL or PostgreSQL — separate from the databases you manage
HTTPS
required for passkeys (except on localhost)
Optional
ssh for tunnels; mysqldump, pg_dump, sqlite3 for backups; a worker for large exports

{{ symbol:circle-alert }} FAQ

Frequently asked questions

What does phpdbadmin cost? {{ symbol:chevron-down }}

Nothing. phpdbadmin is open source under the MIT licence, including commercial use. You run it on your own server or web hosting.

Is phpdbadmin related to phpMyAdmin? {{ symbol:chevron-down }}

No. phpdbadmin is an independent project with its own code and belongs neither to phpMyAdmin nor to phpPgAdmin. Unlike those, it works with four databases in one interface.

Does my data leave the server? {{ symbol:chevron-down }}

No. phpdbadmin runs on your side and reports nothing back — no telemetry, no statistics.

The only exception is the SQL help with AI: it is off until your installation switches it on, and then every account needs its own key. Only your question and the schema (tables, columns, types, keys) are sent — never data.

Which databases and versions are supported? {{ symbol:chevron-down }}

MariaDB 10.6 and later, MySQL 8.0 and later, PostgreSQL 14 and later, and SQLite. The tests run against the current versions and against these minimums.

Do I need HTTPS? {{ symbol:chevron-down }}

For passkeys, yes — browsers only allow them over HTTPS (except on localhost). For a tool with access to your databases, HTTPS is a must anyway; most hosting providers switch on a free certificate with one click.

Can several people work with it? {{ symbol:chevron-down }}

Yes. You invite colleagues by email and grant privileges per connection: read, write or manage. Every writing action is in the audit log, and active sessions can be ended at any time.

Why does the installer need a (sub)domain of its own? {{ symbol:chevron-down }}

So that the program can live outside the web folder and only the public part is reachable. In a subfolder of an existing website that is not possible safely — which is why the installer sets phpdbadmin up on a (sub)domain of its own only.

How do I update? {{ symbol:chevron-down }}

With a console: git pull and then composer upgrade — that fetches the dependencies, builds the interface, runs the migrations and checks the system. New versions are listed under Releases.

Is there a hosted version? {{ symbol:chevron-down }}

No, on purpose. A tool that opens your databases belongs on your server — next to the databases, not with a provider in between.
